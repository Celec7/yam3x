# Architecture and ownership

yam3x is a source registry for Vue applications. The package a user adopts is the copied source in their app. VitePress documents the public API and hosts interactive demos; CLI integration tests generate a disposable consumer to verify copied source independently. The CLI reads the local registry.

| Owner                                                                         | Responsibility                                                                       |
| ----------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| [`registry/foundations`](../registry/foundations)                             | Shared token data, generated semantic token CSS, styles, and dynamic theme functions |
| [`registry/components`](../registry/components)                               | Copyable Vue components, public props, slots, and local helpers                      |
| [`pnpm-workspace.yaml`](../pnpm-workspace.yaml)                               | Canonical dependency version ranges through the pnpm workspace catalog               |
| [`registry/foundations/registry.json`](../registry/foundations/registry.json) | Explicit source-to-target mappings for foundation files and foundation-only tools    |
| [`registry/package.json`](../registry/package.json)                           | Runtime, peer, and foundation setup package policy                                   |
| [`packages/cli`](../packages/cli)                                             | Copy source into a target app and reconcile declared npm dependencies                |
| [`scripts/generate-registry.mjs`](../scripts/generate-registry.mjs)           | Derive component entries and dependency closures from source imports                 |
| [`apps/docs`](../apps/docs)                                                   | VitePress component docs, direct registry demos, unit and browser verification       |
| [`packages/cli/test`](../packages/cli/test)                                   | Generate disposable Vue/Vite consumers; typecheck and build installed sources        |

The theme functions use Material Color Utilities. Switch, Dialog, and BottomSheet use Ark UI for behavior. Button variants use plain TypeScript class selection. The registry generator derives package requirements from source imports and resolves versions through the workspace catalog. It writes generated metadata into the ignored [`packages/cli/registry`](../packages/cli/registry) directory during `prepack`; the CLI reads that artifact. Component and foundation styles are standard CSS and need no styling build integration. Floating overlays acquire their stacking order from [`registry/components/_shared/overlay-layer.ts`](../registry/components/_shared/overlay-layer.ts); components do not hard-code overlay z-index values.

The CLI copies files only when the destination is missing. Core initialization also distributes its design-routing `AGENTS.md` to `src/components/yam3x/` when one is absent, keeping its scope on the copied YAM3X components. Once installed, the app owns copied changes. The CLI records `yam3x.lock.json` as a per-file upstream baseline; `adopt` records the 0.6.0 baseline for existing installs, `status` reports dependency and source summaries, and `diff` classifies local and upstream drift without writing source. `upgrade --apply-clean` copies only `upstream-only` files and advances their entries; a local journal reconciles interrupted applies, `--resolve` advances a resolved conflict, and `--finalize` refuses while blocking states remain. `sync` updates dependency declarations without touching copied source. Run `pnpm registry:check` after changing component imports, dependency policy, or foundation mappings; `pnpm registry:prepare` writes local CLI metadata for development. The [contributing guide](../CONTRIBUTING.md) lists the checks for that work. External sources and their roles are recorded in [References](design/references.md).

Shared UI language is scoped to Vue provider trees rather than process-wide mutable state. Locale dictionaries and message contracts live in `registry/components/localization`; components own their behavior and read resolved messages through that module. Application labels and server errors remain application-owned. See the [localization usage guide](../apps/docs/components/localization.md) for configuration and fallback behavior.

For CSS and theme-token ownership, see [CSS and token conventions](design/css-and-tokens.md).
