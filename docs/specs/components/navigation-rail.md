# Navigation rail: project design guide

## Scope

A navigation rail switches between top-level destinations along the leading edge of a layout. Material 3 Expressive defines collapsed and expanded rails; the baseline rail is no longer recommended. The expanded rail replaces the navigation drawer for updated designs.

## Design target

- `navigation-rail.adaptive.layout`: Use the navigation rail in medium and larger layouts, with the navigation bar in compact layouts. The [adaptive guidance figures](https://m3.material.io/components/navigation-rail/guidelines) show the rail's placement and relationship to surrounding content.
- The overview recommends three to seven destinations and allows one optional FAB. This is design guidance; destination count remains the consuming application's information-architecture choice.
- Use an outlined icon for inactive destinations and a filled icon for the selected destination when the icon family provides both. See [Navigation rail accessibility: visual indicators](https://m3.material.io/components/navigation-rail/accessibility).
- Keep the rail vertical at the leading edge, outside content panes. Mirror its position in RTL. See [Navigation rail guidelines: placement](https://m3.material.io/components/navigation-rail/guidelines).
- `navigation-rail.geometry.collapsed`: Use the collapsed variant for primary destinations and the expanded variant when secondary destinations or labels need more space. The expanded rail replaces the legacy navigation drawer. See [Navigation rail overview](https://m3.material.io/components/navigation-rail/overview) and [specifications: variants and anatomy](https://m3.material.io/components/navigation-rail/specs).
- Make the active destination clear with the indicator and selected icon treatment in the [state figures](https://m3.material.io/components/navigation-rail/specs). Keep the entire destination row as its interaction target in the expanded form. See [Navigation rail guidelines](https://m3.material.io/components/navigation-rail/guidelines).
- Keep destination labels visible at increased text size; allow wrapping instead of truncating or shrinking them. Place badges at the icon in collapsed mode and beside the label in expanded mode. See [Navigation rail guidelines: text scaling and badges](https://m3.material.io/components/navigation-rail/guidelines).
- `navigation-rail.color.contrast`: Use the official color roles and state treatment shown in the [light and dark color figures](https://m3.material.io/components/navigation-rail/specs). Maintain at least 3:1 icon contrast. See [Navigation rail accessibility: contrast](https://m3.material.io/components/navigation-rail/accessibility).
- `navigation-rail.a11y.keyboard`: Expose a labeled navigation landmark, clear destination names, and visible keyboard focus. Support keyboard movement and selection as shown in [Navigation rail accessibility](https://m3.material.io/components/navigation-rail/accessibility).

Navigation rail styles consume private `--_yam3x-navigation-rail-*` aliases declared on the component root. No Navigation Rail CSS custom-property override is part of the public API; component props and slots are documented on the public [Navigation rail page](../../../apps/docs/components/navigation-rail.md).

## Project decisions

- Project-defined: Navigation items represent destinations and retain native link semantics. The application owns routing and whether each destination's state is preserved or reset.
- Project-defined responsive mapping: `mode="auto"` hides the rail below 960 px so the consuming layout can show Navigation Bar for compact windows. The numeric breakpoint belongs to this project; Material specifies the compact Bar and medium-or-larger Rail arrangement without prescribing numeric boundaries.
- Project-defined: Use the filled `surface-container` rail surface although Material allows the container fill to be omitted when contrast requirements are met.
- Project-defined: Support the standard 96dp collapsed rail and 220–360dp expanded rail; the narrow 80dp collapsed variant is outside this component's current scope.
- Project-defined: Keep the menu icon aligned with the destination icon axis in both forms. The expanded destination's 16dp inset and 8dp icon-label gap follow the horizontal item layout. Separate header-to-destination spacing and outer surface padding are layout choices.
- Project-defined: Use a 40dp gap between the header and destination list, and 20dp outer surface padding. Expanded destinations have no inter-item gap, matching the selector's deprecated zero-space value.
- Project-defined: Disabled destination icon and label use `on-surface` at 38% opacity. Material's rail token selector does not provide a disabled color mapping.
- The project component follows the current collapsed/expanded expressive rail. Exact props, slots, events, breakpoints, and examples belong to its source and the public [Navigation rail page](../../../apps/docs/components/navigation-rail.md).
